## Что здесь

Аналитический пайплайн и система мониторинга сервиса подписки ПРАЙМ. Проект загружает транзакционные и профильные данные из базы PostgreSQL, проверяет качество сырых данных, рассчитывает юнит-экономику и строит клиентскую аналитическую витрину без двойного счёта с независимым контролем денег и аудитом через протокол сборки. В рамках второго этапа проведена декомпозиция влияния изменения цен на выручку сегмента (Исследование А).

## Как запустить

Нужны [Git](https://git-scm.com/) и [uv](https://docs.astral.sh/uv/).
Python отдельно ставить не нужно — его поставит uv.

```bash
git clone git@github.com:NastyaTrotsenko/prime-monitor.git
cd prime-monitor
uv sync
```

Доступ к учебной базе выдаёт бот курса по команде `/db`. Полученную строку
подключения кладём в `.env`:

```bash
cp .env.example .env
# и вписать в .env строку из бота
```

Проверка, что всё встало:

```bash
uv run python -c "from prime.config import get_engine; print(get_engine().connect().execute(__import__('sqlalchemy').text('select current_user')).scalar())"
```

Запуск JupyterLab:

```bash
uv run jupyter lab
```

## Что здесь считается

Что здесь считается
Выручка сегмента (paid): сумма всех платежей клиентов сегмента со статусом success за анализируемый период (январь — июнь 2026). Неуспешные платежи исключены.
Зерно витрины клиента (mart): один клиент выделенного сегмента — ровно одна строка (client_id). Агрегаты платежей и участий предварительно сворачиваются до клиента во избежание декартова размножения строк.
Флаг активности пользователя (uses_prime): клиент считается пользующимся сервисом, если он является владельцем подписки (subscription_id is not null) или состоит участником хотя бы в одной чужой семейной подписке (n_memberships > 0).
Эффект цены vs объёма (Исследование А): чистый ценовой эффект мартовского подорожания рассчитывается как разница между фактической выручкой после 1 марта и гипотетической выручкой по старым тарифам на том же числе оплат.
